## 實作與回歸

- Telnet 使用串流狀態機處理跨封包 IAC／協商，維持 Big5 原始位元組；提供 VT100 與 80×24 視窗。
- 上游握手前輸入有界排隊；空訊息略過。socket 關閉、錯誤、開發服務重啟都清理上游連線。
- 來源限制為 loopback Host 與同源 Origin，防止僅比較兩者相等所留下的 DNS rebinding 缺口。
- 以受控上游 WebSocket 延遲握手，透過 ping/pong 確認代理已收到輸入後才完成握手，驗證排隊順序，不依賴固定等待。
- Vitest 使用無 HTTP server 的 Vite middleware mode，該模式不安裝代理；dev 測試另用 Node 設定，避免前端 polyfill 干擾 TCP 模組。
- `tsconfig.node.json` 納入代理與測試；新測試已加入預設 `npm test`。
- 登入與首頁只顯示連線目標，不載入帳密；移除原有「不會上傳任何伺服器」的不正確說明。

## 推文格式差異（後續修正）

- 本機 `imageptt` 的確認畫面為 `ID:內容`，正式站為 `ID: 內容`。先前 browser 量到本機容量後仍用正式站格式做讀回預檢，因此在送出任何片段前回報容量不一致。
- `pttzzz2` 是 7 個半形字元；原先按 8 字元估算造成「還差一欄」的誤判。現有 78 欄模型只需將本機的冒號後分隔空格設為 0，便得到本機量到的 54 欄，不另加特殊欄寬常數。
- Vite 依連線目標傳送安全的 `local`／`ptt` 格式標記給 browser。browser 用它核對確認畫面、規劃分段；core 依讀回文字是否有分隔空格計算剩餘容量。正式模式維持一格半形空白。
- 回歸測試覆蓋本機無空格與正式站有空格的確認、分段、讀回聚合；正式站未寫入。以不同客戶端產生、正文原本以空白開頭的本機推文，單靠文字無法和正式站分隔空格區分，須另以來源資訊解決。

## 第二階段：串流與操作相容性

以下先記錄追加重構前的檢查點；最終狀態見下方「追加重構與驗證」。

- 接收端改為獨立 `StreamingPtt` 適配器，固定上游 `ptt-client` 版本。Big5 未完成字元跨訊息保留，ANSI 狀態由終端延續；單訊息上限 1 MiB，解碼分批處理。補超過 1,024 bytes、跨訊息中文字與 ANSI、斷線及繼承 `send()` 的測試。
- 儲存提示依明確畫面分類為 `s`／`y`；取消選單使用 `a`／`n`。本機發文分類須觀察數字回顯後補 Enter，不以固定等待判定選擇完成。

- 在本機 Gossiping 自建文章驗證發文、短回文及六段長回文；讀回正文與草稿逐字相同，包含空白行及符號。未登入正式站。本輪測試文已由原生刪文流程清除，再次列文找不到該作者／標題；不代表底層實體文章檔已移除。
- 編輯文章實測發現既有流程以正文行數刪除整份編輯檔，會破壞作者／標題。新增回歸與安全阻擋；尚未完成完整編輯緩衝區的正文替換及儲存讀回。是否本階段重構待確認。

### 回文失敗指引

- 移除零片段送出前失敗時一律顯示「請檢查內容」的處理。`GatewayError`／`CoreError` 增加可選 `replyIssue`，保留既有錯誤碼與 outcome；舊 gateway 不提供分類時使用未知原因指引。
- browser 以實際 UAO 編碼檢查超限欄數及不支援字元，再進行終端準備；連線、文章定位、輸入欄位確認與分段還原問題分開回報。不以錯誤訊息文字猜分類。
- UI 顯示超出字數或待替換字元；文章狀態失效提供唯讀重新載入，保留草稿且不重送。連線失效提醒先複製草稿再重新登入，不宣稱登入／頁面重載後草稿仍會保存。
- 已送出部分片段或送達不確定仍沿用既有鎖定與續送機制；本次分類不將未知寫入轉為可安全重試。

- 獨立審查補齊分段開頭空白的分類，以及 Tab／控制字元的修正指引；容量與格式分類、唯讀重新載入 reject 皆納入 UI 回歸。
