# Goal 7 編輯功能設計

## 目標

完成文章編輯與既有回文編輯流程，並確保所有 PTT 寫入只有在終端狀態可驗證時才送出。文章編輯只替換正文，既有簽名檔、推文、PTT 編輯紀錄及 PTTzzz 編輯摘要必須保留。

## 範圍

本階段包含：

- 載入既有文章內容至文章編輯頁
- 透過 PTT 原生文章編輯器更新正文
- 將編輯摘要保存為可解析的 PTT 文章內容
- 在 pttzzz 將編輯摘要顯示於正文末端、回文上方
- 透過新推文表達補充、更正與撤回既有回文
- 明確呈現寫入中、成功與失敗狀態
- 讓 fake adapter 實際保存文章及回文編輯結果

本階段不包含文章刪除、實站自動寫入測試或變更 `dev-notes/spec.md`。

## 編輯摘要保存格式

編輯摘要使用固定單行標記保存於 PTT 文章可編輯內容末端：

```text
※ PTTzzz 編輯摘要：修正數據來源
```

摘要在寫入前會：

- 移除換行與終端控制字元
- 去除首尾空白
- 限制最大長度，避免超出 PTT 編輯器安全範圍
- 拒絕空摘要

parser 將此標記從正文抽離，建立結構化 revision record。若其後存在 PTT 原生 `※ 編輯:` 紀錄，兩者依文章中的先後順序配對；無法配對時仍保留摘要，不把它重新當成正文。

## 文章內容邊界

文章資料需區分：

1. 可修改正文
2. 簽名檔
3. PTTzzz 編輯摘要
4. PTT 原生編輯紀錄
5. 推文區

文章編輯頁只允許修改第一項。送出前由 adapter 以原始文章資料重新組合其他區段，保持原始順序與內容。若無法可靠辨識邊界，編輯流程必須取消，不得猜測後送出。

## Adapter 寫入流程

文章編輯 API 必須攜帶看板、文章 index 或 AID，以及預期的文章作者與標題。adapter 在序列化 command queue 中執行：

1. 確認登入狀態。
2. 離開目前可能存在的文章閱讀器或中介畫面。
3. 進入指定看板並開啟指定文章。
4. 驗證作者與標題，防止文章 index 變動後編輯到其他文章。
5. 送出 PTT 編輯命令並確認進入文章編輯器。
6. 僅替換可修改正文，重新附加原簽名檔、歷史摘要與新摘要。
7. 觸發儲存，逐步辨識確認提示。
8. 確認回到文章或看板畫面後才回傳成功。

任何畫面不符合預期、逾時、權限不足或文章身分不一致時，adapter 會嘗試取消編輯並回傳具體失敗原因。API 不以「已送出按鍵」作為成功依據。

## 回文編輯語意

PTT 不提供原地修改推文，因此回文編輯以新增一則推文保存歷史。統一格式為：

```text
補充我在12樓發言：新增內容
更正我在12樓發言：替代內容
撤回我在11~13樓發言
```

補充與更正預設使用箭頭類型；撤回固定使用箭頭類型。目標樓層取自聚合回文的 `sourceFloors`，單樓使用第一個原始樓層，範圍撤回使用最小與最大原始樓層。

送出成功後重新讀取文章，由 parser 與 aggregator 產生更新後的顯示模型。UI 不以本地 overlay 假裝 PTT 已寫入成功。

## UI 資料流

文章頁開啟編輯時，將目前文章的看板、index 或 AID、標題、作者、正文、簽名檔與 revisions 傳入編輯 view。編輯頁顯示可修改正文及唯讀歷史紀錄。

送出期間按鈕停用。成功後返回原文章並重新載入；失敗時保留使用者輸入與編輯視窗，顯示 adapter 回傳的原因。

文章閱讀頁在正文與回文列表之間顯示可展開的編輯紀錄。摘要使用獨立樣式，不交給正文的 rich-content renderer。

回文 Composer 送出補充、更正或撤回後，只有 adapter 回傳成功才關閉。失敗時保留內容並顯示錯誤。

## Fake Adapter

Fake adapter 使用與正式 adapter 相同的公開 API：

- 文章編輯會更新目標文章正文並新增結構化摘要資料
- 回文編輯會新增符合規格的 raw push
- 找不到文章、未登入或作者不符時回傳失敗

Preview 與單元測試不得再以無條件 `{ ok: true }` 模擬尚未發生的寫入。

## 測試策略

測試採用 TDD，依序涵蓋：

- parser：摘要標記抽離、歷史順序、控制字元及未配對紀錄
- adapter：文章定位、身分驗證、編輯器狀態、儲存確認、取消與逾時
- action hook：完整參數轉交與錯誤結果
- fake adapter：正文與 raw push 確實更新
- UI：既有內容預填、revision 區塊、送出中狀態、成功 reload、失敗保留輸入
- regression：一般發文、一般回文、投票與文章解析行為不受影響

驗證只使用模擬終端與 fake adapter。未取得明確授權及測試帳號前，不對真實 PTT 執行文章或推文寫入。

## 安全條件

- 不依賴固定 sleep 判定成功；sleep 僅用於讓終端更新，狀態轉移仍由畫面 pattern 驗證
- 寫入前後均驗證文章身分
- 不辨識的畫面一律失敗並取消
- 不在 log、debug dump 或錯誤訊息輸出帳號密碼
- 不修改、刪除或重排既有推文與編輯紀錄
