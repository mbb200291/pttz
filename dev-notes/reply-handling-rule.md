# 推文聚合與回覆處理規則

本文件以 [`goal-7-vote-model-review.html`](goal-7-vote-model-review.html) 為準，說明 PTT 原始推文如何轉換為 pttzzz 的文章分數、回文評分與討論串。

## 1. 基本資料模型

每一筆 PTT 推文同時具有兩個彼此獨立的訊號：

1. **PTT 類別**：`推`、`噓`、`→`
2. **內容 intent**：一般留言、巢狀回覆、文章投票、回文投票、編輯或撤回

兩者不能混為同一種分數：

- **文章原生分數**只看 PTT 類別：`推 +1`、`噓 -1`、`→ 0`。
- **回文評分**只看內容行首的回文投票 pattern，不受 PTT 類別影響。

因此，其他客戶端送出的 `噓 alice: 推12樓` 會同時造成：

- 文章原生分數 `-1`
- 原始 12F 的回文評分 `+1`

pttzzz 自己送出回文投票或帶投票的回覆時，一律使用 PTT `→` 類別，避免把應用層回文評分額外計入文章原生分數。

## 2. 先解析 intent，再決定聚合

每一筆原始推文先依行首 pattern 分類，再進入聚合流程。解析只執行一次；從 pattern 取出的 body 不再遞迴解析。

處理順序：

```text
原始推文
  → 解析 PTT 類別與行首 intent
  → 執行編輯／撤回狀態
  → 隱藏無 body 的控制事件
  → 依作者、結構目標、時間與終止符聚合可見 body
  → 依原始樓號建立巢狀關係
  → 計算文章原生分數與回文最後投票狀態
```

## 3. 一般留言與文章投票

### 一般留言

不符合控制或巢狀 pattern 的文字是一般可見留言，並形成回文卡片。它的 PTT 類別仍照常計入文章原生分數，但不會讓自己的回文評分增加或減少。

```text
推 alice: 好文
```

結果：文章原生分數 `+1`，Alice 的留言可見，該留言的回文評分為 `0`。

### 純文章投票

內容去除前後空白後只有 `推` 或 `噓` 時，視為文章投票：

- 不生成討論串卡片。
- PTT 類別仍計入文章原生分數。
- 文章投票按鈕依應用層狀態顯示投票人數。

```text
推 alice: 推
噓 bob: 噓
```

## 4. 巢狀回覆

巢狀回覆 pattern 必須出現在行首。支援的形式包括：

- `回x樓：body`
- `回xF body` / `回xf body`
- `TO xF body`
- `reply to xF body`
- `>>xF body`

pattern 只建立巢狀關係，不是回文投票。顯示時移除 pattern，只保留 body。

```text
推 bob: 回12樓：同意你的看法
```

結果：Bob 的 body 掛到原始 12F 下方；PTT 推類別讓文章原生分數 `+1`，但 12F 的回文評分不變。

## 5. 回文投票與複合回覆

### 支援的投票 pattern

- `推x樓`
- `x樓推一個`
- `噓x樓`

pattern 決定目標樓與投票方向，忽略該筆事件的 PTT 類別。

### 純回文投票

pattern 後沒有 body 時是隱藏控制事件：

```text
→ alice: 推12樓
```

結果：原始 12F 的回文評分 `+1`，不新增 Alice 的回文卡片，文章原生分數不變。

純投票必須獨立處理，不可與前後一般留言聚合，也不可吞掉下一則留言。

### 投票加回覆

pattern 後有 body 時，同一筆事件同時代表投票與巢狀回覆：

```text
→ alice: 推12樓 我同意這個觀點
```

結果：

- 原始 12F 得到 Alice 一票推。
- `我同意這個觀點` 顯示為 12F 的巢狀回覆。
- body 不再當成新的 pattern 解析。

複合事件的可見 body 可以與相同作者、相同結構目標的後續 body 聚合；投票仍只按該帳號的最後狀態計算一次。

## 6. Pattern 邊界

所有控制與巢狀 pattern 都必須符合以下條件：

- 從行首開始。
- `推x樓`、`噓x樓`、`回x樓` 等樓號在尾端的前綴，樓號後必須結束，或接至少一個半形／全形空白，或冒號 `:`／`：`。
- `x樓推一個` 必須完整符合固定片語；片語後同樣必須結束或以空白／冒號分隔 body。
- pattern 後取出的 body 不再遞迴解析。

```text
推12樓主的整理很清楚
```

`樓` 後直接接 `主`，因此整句是一般可見留言，不投票，也不掛到 12F。

## 7. 回文投票去重與改票

同一帳號對同一目標樓只保留最後投票方向：

```text
→ alice: 推12樓
→ alice: 噓12樓
```

結果：Alice 對 12F 最終只有一票噓。

同方向重複投票仍只計一票。pttzzz 送出端應阻止同一帳號重複送出相同方向；其他客戶端留下重複事件時，解析端仍須去重。

帶 body 的複合事件改票時，只更新投票狀態，不刪除先前已發表的可見 body：

```text
→ alice: 推12樓 我同意第一點
→ alice: 噓12樓 但不同意第二點
```

結果：12F 對 Alice 最終是一票噓，兩段可見回覆都保留。

## 8. 推文聚合

### 分群條件

同作者的可見推文在以下條件全部成立時可聚合：

- 前一片段允許續接。
- 兩片段連續，或時間差不大於 5 分鐘。
- 結構目標相同；不同巢狀目標不得合併。

前一片段符合下列任一條件時允許續接：

- 末尾沒有終止符 `.`, `。`, `!`, `?`, `！`, `？`, `;`, `；`
- 末尾具有強制續接符 `||`

`||` 會從顯示內容移除；即使它前面已有終止符，也必須與後續片段聚合。

### 內容連接

- 依 PTT 推文輸入容量計算後，前一行剩餘可輸入欄寬少於兩個終端欄位、已塞不下一個全形中文字時直接拼接。
- 非滿行以換行連接。

### 交錯作者

不連續但仍在時間限制內的同作者片段可以聚合。聚合時必須保留每一段的原始樓號；其他回覆指向其中任一原始樓號，都應解析到同一張聚合卡片。

兄弟節點依首次出現的原始樓號排序。

### 巢狀回覆續行

巢狀回覆也使用相同聚合規則。第一段的結構目標會延續到沒有新 pattern 的後續片段：

```text
→ alice: 推12樓 我先說第一點
→ alice: 接著補充第二點。
→ alice: 回8樓：這是另一個目標
```

前兩行可聚合為 12F 下的一張卡片；第三行因目標改為 8F，必須另開群組。

## 9. 原始樓號與最大巢狀深度

- 所有 `x樓` 永遠指向原始 PTT 推文樓號，一行一樓。
- 隱藏投票與控制事件仍占原始樓號，不重新編排後續樓號。
- 聚合卡片保留完整原始樓號集合，供回覆、投票、編輯與撤回定位。
- UI 最多顯示三層。第四層以上的回覆提升為第三層同層節點，但背後仍保留原始目標關係。

## 10. 編輯規則

編輯指令先定位原始事件，再更新該事件的顯示內容。編輯 payload 是 opaque text，不可再次套用回覆或投票 pattern。

```text
噓 alice: 推12樓 我不同意
→ alice: 更正我在13樓發言：回99樓：我改過的文字
```

原始 13F 已被解析為「對 12F 投一票推＋巢狀回覆」。Replace 只把 body 改成 `回99樓：我改過的文字`；它仍掛在 12F，投票方向仍為推，內文中的 `回99樓` 只作為顯示文字。

## 11. 撤回規則

### 撤回回文投票

```text
撤回我對x樓的推
撤回我對x樓的噓
```

只取消該帳號對目標樓的應用層投票，不刪除複合事件已留下的可見 body。pttzzz 使用 `→` 類別送出，控制事件本身隱藏。

### 撤回整則發言

```text
撤回我在x樓的發言
撤回我在x~y樓的發言
```

以原始樓號鎖定事件或聚合範圍。若目標是「投票＋回覆」複合事件，body 與該事件帶來的投票必須一起撤回。Withdraw 後保留一個空格作為內容占位。

### 撤回文章投票

PTT 原生推噓無法刪除。pttzzz 撤回文章推票時送出一筆反向的純文章票抵銷原生分數，並把應用層文章投票狀態清零：

- 撤回推：送出 PTT `噓` 類別與純內容 `噓`
- 撤回噓：送出 PTT `推` 類別與純內容 `推`

反向事件同樣不生成討論串卡片。

## 12. 核心不變量

1. PTT 類別只決定文章原生分數。
2. 行首內容 pattern 只決定應用層 intent、回文目標與回文評分。
3. 無 body 的控制事件隱藏；有 body 的回文投票是可見的投票加回覆。
4. 同帳號、同目標樓的回文投票只保留最後方向。
5. 編輯 payload 不重新解析。
6. 投票撤回與發言撤回是兩種不同操作。
7. 聚合、回覆、投票、編輯與撤回都使用原始 PTT 樓號。
