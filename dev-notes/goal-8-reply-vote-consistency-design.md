# Goal 8：回文投票一致性設計

## 目標

統一回文投票人數、回文分數與推噓分排序的資料來源，並阻止同一回文在送票尚未完成時因快速連點而重複送出 PTT 推文。

## 範圍

本目標處理：

- `推x樓`、`x樓推一個`、`噓x樓` 對目標回文的計分。
- 同一使用者對同一回文的投票去重與最後狀態採計。
- PTTzzz 介面送出回文投票時的重複提交防護。
- 純投票推文隱藏後的樓號顯示與投票目標一致性驗證。

本目標不處理：

- 文章層級與回文層級的投票撤回指令；另列 Goal 9。
- 回文 Append、Replace、Withdraw 編輯紀錄；另列 Goal 10。
- 文章刪除、Imgur 短網址與整體 UI 稿驗收。

## 分數定義

回文分數採用唯一公式：

```text
score = pushVoters.length - booVoters.length
```

只有符合明確投票格式的推文會影響目標回文分數：

```text
推x樓
x樓推一個
噓x樓
```

`回x樓：內容` 是一般巢狀回覆。無論該回覆在 PTT 使用推、噓或箭頭類別送出，皆不影響被回覆回文的 `score`。

同一 ID 對同一目標的採計規則：

- 相同方向重複出現只計一次。
- 推與噓皆出現時採最後一筆有效投票。
- `pushVoters` 與 `booVoters` 不得同時包含同一 ID。

因此 VotePair 顯示人數、卡片推噓分與推噓分排序都使用相同狀態，不再混用一般巢狀回覆的 PTT 類別。

## 送票流程

送出回文投票時，以回文 ID 為單位維護進行中狀態：

1. 點擊推或噓時，同步檢查該回文是否已有送票請求。
2. 若已有請求，忽略後續點擊，不呼叫送票 action。
3. 若沒有請求，立即標記該回文為進行中，再呼叫送票 action。
4. 進行中期間，同時停用該回文的推與噓按鈕；其他回文仍可投票。
5. 成功後套用投票結果並重新載入文章資料。
6. 失敗時保留原投票狀態並顯示既有錯誤訊息。
7. 無論成功或失敗，請求結束後解除該回文鎖定。

同步 guard 是必要條件。僅依賴 React state 重新渲染不足以攔截同一事件迴圈內的連續點擊。

## 元件與資料流

### `pushAggregator.ts`

- 保留現有特殊投票解析與 voter 去重邏輯。
- 移除一般巢狀回覆對父回文 `score` 的累計。
- 完成 voter 收集後，由 voter 陣列計算每則回文的 `score`。
- 純投票推文仍不作為獨立回文顯示。
- 驗證隱藏投票推文前後，UI 顯示樓號與下一次 `推x樓／噓x樓` 的目標解析一致。

### `Article.tsx`

- 以同步集合記錄正在送票的回文 ID，作為防重的權威狀態。
- 以 React state 映射相同集合，驅動按鈕 disabled 顯示。
- 在呼叫 `votePush` 前取得鎖定，在 `finally` 解除鎖定。

### `PushThread.tsx` 與 `VotePair.tsx`

- 將該回文是否正在送票傳到 VotePair。
- 送票期間同時停用推與噓按鈕。
- 不增加全域投票鎖；不同回文可各自送票。

## 錯誤處理

- 重複點擊是無操作，不顯示額外錯誤。
- PTT action 回傳失敗時沿用目前錯誤呈現，不做樂觀票數變更。
- 失敗後必須解除鎖定，允許使用者重試。
- 不在 adapter 建立新的投票佇列；adapter 保持負責既有 PTT 命令序列化。

## 測試與驗收

### 聚合器

- 兩個不同 ID `推1樓` 時，目標回文為兩票且 `score` 為 `+2`。
- 同一 ID 重複推同一樓時只計一票。
- 同一 ID 先推後噓時，`score` 由 `+1` 變為 `-1`。
- 一般 `回1樓：內容` 即使使用推或噓類別，也不改變父回文 `score`。
- 混合明確投票與一般巢狀回覆時，`score` 僅反映明確投票。
- 純投票推文不顯示，且後續顯示樓號可被 UI 送出的樓號正確投票。

### 互動

- 使用未完成的 Promise 模擬送票，快速點擊同一回文兩次只呼叫一次 `votePush`。
- 請求期間該回文的推與噓按鈕皆停用。
- 同時點擊另一回文仍可送出另一個請求。
- 成功與失敗後按鈕都會恢復可操作。
- 失敗不改變原本的 voter 人數或目前使用者投票狀態。

### 完整驗證

```bash
npm test
npm run lint
npm run build
```

## 不採用方案

- 不只依賴解析端去重：重複推文已經送到 PTT，仍會消耗推噓限制並污染原始紀錄。
- 不把目標鎖放進 adapter：adapter 不應管理 React 畫面的回文 ID 與按鈕狀態。
- 不合併明確投票分數與巢狀回覆類別：同一使用者可能被重複計分，且 VotePair 人數無法解釋總分。
