# Goal 7 回文推噓控制修正設計

## 問題

目前 `Article` 將「作者只能用 `→` 回覆自己的文章」套用到所有 Composer 模式，導致作者回覆特定樓層時也無法選擇推／噓。這與 pttzzz 的回文解析模型不符：針對樓層的推噓由內容 pattern 表達，可使用 PTT 的 `→` 類別送出。

回文卡片的推噓按鈕則在送出後立刻進入 pending 狀態，但要等 PTT 成功回應才更新票數與選取狀態。等待期間按鈕被鎖住且沒有視覺上的成功回饋或失敗訊息，因此看起來像無法點擊。

## 行為定義

### 直接回覆文章

- 文章作者只能選擇 `→`，並顯示 PTT 警語「作者本人, 使用 → 加註方式」。
- 非作者維持推／→／噓三種 PTT 原生類別。

### 回覆特定樓層

- 不受文章作者限制，所有登入使用者均可選擇推／→／噓。
- pttzzz 統一以 PTT 的 `→` 類別送出，並以內容 pattern 表達語意：
  - 推：`推x樓 回覆內容`
  - →：`回x樓：回覆內容`
  - 噓：`噓x樓 回覆內容`
- 推／噓 pattern 同時形成可見的巢狀回覆，並計入目標樓層的回文評分。

### 回文卡片推噓

- 點擊後立即套用 optimistic UI，顯示新的選取方向與票數。
- 同一樓層在 PTT 回應完成前維持鎖定，避免重複送出。
- PTT 成功後重新載入文章確認狀態。
- PTT 失敗時回復點擊前的狀態、解除鎖定，並在討論串上方顯示失敗原因。
- 實際送出仍沿用現有 `votePush`／`withdrawPushVote`，其底層使用 `→` 與隱藏 pattern，不受作者不能推噓自己文章的限制。

## 實作範圍

- `Article.tsx`：依 Composer 模式決定 `neutralOnly`；格式化樓層回覆；調整回文投票的 optimistic state 與錯誤呈現。
- 現有 `Composer`、`PushThread` 與 adapter 介面保持不變，避免新增抽象。
- 不修改 `dev-notes/spec.md`。

## 驗證

- 作者直接回覆文章時，推／噓仍停用。
- 作者回覆特定樓層時，三種方向均可選。
- 特定樓層的三種回覆方向均以正確內容及 raw `neutral` 送出。
- 回文卡片投票在 promise 尚未完成時已顯示 optimistic 結果且阻擋連點。
- 回文卡片投票失敗時回復原狀並顯示原因。
- 完整測試、TypeScript build 與 lint 通過。

## Follow-up：文章統計、回文卡片與作者輸入畫面

### 文章統計列

- 保留 PTT 原生「推」與「噓」數量。
- 將原生「中立」數量改為 pttzzz 解析後的「回覆」總數。
- 回覆總數包含所有可見、聚合後的第一層與巢狀回覆。
- 回覆總數排除純文章／回文投票、撤回等隱藏控制事件，以及 synthetic edit 紀錄。
- 統計必須採用與 `PushThread` 相同的可見性判斷，避免頂部數字與畫面卡片不一致。

### 回文卡片

- 保留 raw PTT 類別 badge「推／噓／→」，讓使用者仍可辨認原始事件類別。
- 移除卡片標頭的淨分 badge「推 +1／噓 -1」。
- 回文收到的推／噓人數與目前使用者方向，只由卡片右側 `VotePair` 呈現。

### 作者對回文送出投票

作者在自己的文章按 `X` 時，PTT 可能不顯示一般推文種類選單，而直接顯示「作者本人，使用 → 加註方式」並進入 `→ 帳號:` 輸入狀態。現有 adapter 只辨認一般內容提示，因此會誤回傳 `push-entry-timeout`。

- `submitPushFromCurrentArticle()` 應將作者專用警語辨認為 raw neutral 的內容輸入狀態。
- 只有要求的 `pushType` 是 `neutral` 時才可直接繼續；原生 push／boo 仍不得繞過 PTT 的作者限制。
- pttzzz 的回文投票與複合樓層回覆本來就使用 raw neutral，因此可在此狀態送出 `推x樓／噓x樓` pattern。
- 若未看到一般種類選單、一般內容提示或作者專用警語，仍安全取消並回傳 `push-entry-timeout`。

### Follow-up 驗證

- 統計列顯示「推／噓／回覆」，且回覆數等於可見的非 edit 聚合回覆總數。
- 巢狀回覆納入回覆總數，純投票與 edit 不納入。
- 回文卡片保留 raw PTT badge，且不再顯示淨分 badge。
- 作者專用警語出現時，raw neutral 內容可成功送出。
- 相同畫面若要求 raw push／boo，仍拒絕送出內容。
