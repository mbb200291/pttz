# 目標

1. 一個比較現代的論壇UI，來呈現PTT的看板和文章和討論串
2. 伺服器只提供前端靜態serving，由client side直接打ptt websocket
3. 閱讀文章方面，實作pttzzz頁面回文解析規則 （見#pttzzz頁面回文解析規則）
4. 文章內文的回文列表有按鈕能重新排序第一層聚合後的回文，排序可依據回文時間（預設）、推文數，可遞增和遞減排序
5. 能設定圖像，將頭像連結放在第三方圖片託管平台，實際可以用於顯示在發文和回文，將該圖片的連結放在個人名片區，顯示時需及時讀取該資訊
6. 閱讀體驗 - Basic
7. 發文、回文

# 補充

## ptt回文聚合處理

1. 符合以下規則，將同個作者的分散回文視為同一個回文
   - 連續回文或不連續回文但時間間隔不大於k分鐘，且最後一個字不是回文終止符（以下符號視為回文終止符）
     - `。`
     - `.`
     - `!`
     - `?`
     - `！`
     - `？`
     - `;`
     - `；`
   - 顯示上移除“回x樓“這段文字
   - 特殊符號位於回文末端，用於標示回文必須與後續回文合併：`||`
   - 若單行佔滿，則句子直接拼接下句，若無佔滿則下句保持獨立一行拼接

2. 對某個回文的回文，用以下規則識別
   - “回x樓：...." <- 此處的回x樓作為識別該回文應該是對第x個回文的嵌套回文，依此類推。x 指向原始 PTT 推文樓號，一行一樓
   - 類似pattern
     - `回x樓`
     - `回xf` / `回xF`
     - `TO xf`
     - `reply to xf`
     - `>>xf`
3. 對文章的讚數或扣分數用聚合後第一層回文的“推”總數
4. 對回文的讚或扣分數也類似，用聚合後的回文，且綁定在該回文者
5. 作者的回文需有標籤標示為原發文者
6. 作者的文章編輯則視為對最接近的回文的回覆

## 閱讀體驗 - Basic

- 開啟文章後看到內容的時間不能超過0.5秒，下方回文區塊可能需要逐步渲染
- 進入看板看到文章列表的時間不超過0.5秒
- 看板文章可隨著滾動自動載入
- 自動預覽圖片和youtube影片
- 基本文章讀相關操作，包含搜尋文章、查詢文章id、搜尋文章id、篩選指定推噓文數文章
