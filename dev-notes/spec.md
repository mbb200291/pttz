# 目標

1. 一個更現代的論壇UI，來呈現PTT的看板和文章和討論串
2. 伺服器只提供前端靜態serving，由client side直接打ptt websocket
3. 閱讀文章方面，實作pttzzz頁面回文解析規則 （見#pttzzz頁面回文解析規則）
4. 文章內文的回文列表有按鈕能重新排序第一層聚合後的回文，排序可依據回文時間（預設）、推文數，可遞增和遞減排序
5. 能設定圖像，將頭像連結放在第三方圖片託管平台，實際可以用於顯示在發文和回文，將該圖片的連結放在個人名片區，顯示時需及時讀取該資訊 => 不太可行，先擱置
6. 閱讀體驗 - Basic
7. 發文、回文、對文章或回文按讚或扣分、上傳圖片 （見#pttzzz編輯功能詳述）
8. ptt虛擬模擬器，用於測試回文解析功能
9. 將與ptt原始畫面套用規則的解析模式打包成獨立package，並修正ptt-client的bug
10. UI精緻調整 （見#精緻UI)
11. 另一種替代UI--不分看板閱讀模式，可以不分看板用stream模式瀏覽文章，需做到某種程度的文章推薦
12. 能設定圖像，將頭像連結放在第三方圖片託管平台，實際可以用於顯示在發文和回文，該圖片的連結可能需自架一個key-value cache

# 補充

## ptt回文聚合處理

1. 符合以下規則，將同個作者的分散回文視為同一個回文
   - 連續回文或不連續回文但時間間隔不大於k分鐘，且最後一個字不是回文終止符（以下符號視為回文終止符）
     - `。`
     - `.`
     - `!`
     - `?`
     - `！`
     - `？`
     - `;`
     - `；`
   - 顯示上移除“回x樓“這段文字
   - 特殊符號位於回文末端，用於標示回文必須與後續回文合併：`||`
   - 若單行佔滿，則句子直接拼接下句，若無佔滿則下句保持獨立一行拼接

2. 對某個回文的回文，用以下規則識別
   - “回x樓：...." <- 此處的回x樓作為識別該回文應該是對第x個回文的嵌套回文，依此類推。x 指向原始 PTT 推文樓號，一行一樓
   - 類似pattern
     - `回x樓`
     - `回xf` / `回xF`
     - `推x樓 xxxxxx`  # 此處的xxxx視為回文部分
     - `TO xf`
     - `reply to xf`
     - `>>xf`
3. 對文章的讚數或扣分數用聚合後第一層回文的“推”總數
4. 對回文的讚或扣分數也類似，用聚合後的回文，且綁定在該回文者
5. 作者的回文需有標籤標示為原發文者
6. 作者的文章編輯則視為對最接近的回文的回覆
7. 對文章的推噓按鈕，ui會解析成單一的“推”, “噓”，這一類回文就不顯示在介面上，僅用於顯示文章推噓文數

## 閱讀體驗 - Basic

- 開啟文章後看到部分內容需幾乎即時載入（不超過0.5秒），完整文章和下方回文區塊可稍後載入，但也需要能近乎即時逐步渲染，不應等到所有回文讀入後再一次渲染
- 進入看板看到文章列表的時間需近乎即時載入（不超過0.5秒）
- 看板文章可隨著滾動自動載入
- 自動預覽圖片和youtube影片
- 基本文章讀相關操作，包含搜尋文章、查詢文章id、搜尋文章id、篩選指定推噓文數文章

## pttzzz編輯功能詳述

1. 發文功能，文章編輯頁，插入圖片按鈕
2. 回文
3. 對已有的回文的回覆功能，解析規則如同先前"ptt回文聚合處理"提及，但編輯功能統一用“回x樓：“這個格式
4. 對回文的讚和扣分按鈕，解析規則如下

```
推x樓       ==> 計入x樓一則加分，且不需額外顯示回文
x樓推一個    ==> 計入x樓一則加分，且不需額外顯示回文
噓x樓      ==> 計入x樓一則扣分，且不需額外顯示回文
```

若加扣分透過pttzzz介面，則統一送出“推x樓“、“噓x樓“
注意此處我希望介面能強迫推和噓要走一般回文的推噓（加分必定只能推，扣分必定只能走噓），不能用回覆，這樣能套用ptt看板的推噓文限制。另外解析規則，同一個id，同個推文只會計算一次的推或噓，同時推或同時噓都有的話，則採計後者。從我們ui方面，請阻擋同個id重複的推或噓可以被送出。

5. 對已有的回文的讚和扣分按鈕
6. 修改文章
7. 可修改或刪除某則回文，但可展開回文編輯歷史紀錄：解析規則類似如下，可先以行為單位替換

```

補充我在 12樓 說的：... => Append模式
修正我在 12樓 的說法：... => Replace模式
更正一下我在12樓的回覆：... => Replace模式
撤回我在11~13樓的發言 => Withdraw模式

```

前端會照這個規格解析，而我們這邊的修改按鈕，統一用“補充我在x樓發言：“、”更正我在x樓發言：“、"撤回我在x~y樓發言“
Withdraw模式刪除掉的回文，需保留一個空格

8. 文章刪除功能
9. 請依照此ui稿實作（我把完整設計稿檔案放此處"pttzzz_design/")

10. 發文和回文的插入圖片功能，我希望能串接imgur，然後取得短網址後直接貼上短網址

11. 可收回對文章的推。若從系統方發出，則增加以下回文（使用箭頭類別），另外ui將這類pattern解析成撤回對文章的推噓：
```
撤回我x樓的推文
撤回我x樓的噓文
```

12.  可收回對回文的推或噓。若從系統方發出，則增加以下回文（使用箭頭類別），另外ui將這類pattern解析成撤回對文章的推噓：
```
撤回我對x樓的推
撤回我對x樓的噓
```
