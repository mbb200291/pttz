# pttzzz 核心白皮書重寫設計

## 目標

將 `docs/whitepaper/pttzzz-core.md` 從偏實作規格的 rule-ID 清單，重寫為一般讀者與開發者都能快速理解的白皮書。正文專注於 pttzzz 的願景、三層架構與四組核心解析規則；精確邊界留在技術附錄，完整視覺案例移入 whitepaper 目錄內的獨立 HTML。

正文與案例不得要求讀者先閱讀 `dev-notes`，也不得連結 `dev-notes` 作為規範來源。

## 語氣

前言採簡短、振奮的宣言式語氣，進入架構與規則後轉為清楚、專業的說明。

採用的願景文字：

> 我們要共同打造一個新生的 PTT 社群。
>
> pttzzz 重新解析終端頁面，讓 PTT 在保有原始文化與資料的同時，轉型為現代化社群論壇。聚合分散推文、建立嵌套回文、加入回文推噓與編輯紀錄——這些只是開始。
>
> 我們不只想讓 PTT 繼續存在，更要推動它再次進化，成為下一個世代依然充滿生命力的社群。這場改造沒有終點，只有不斷向前。

## 三層架構

採用工程化名稱：

```text
規則層
定義推文如何聚合、嵌套、投票、編輯與撤回
        ↓
核心層
讀取 PTT 資料，套用規則，輸出穩定的文章與討論結構
        ↓
UI 層
以網頁、行動介面或其他形式呈現，並透過核心執行操作
```

- 規則層回答「終端文字代表什麼」。
- 核心層回答「如何把規則轉為可靠資料與操作」。
- UI 層回答「使用者如何閱讀與參與」。

相依方向固定為 UI 使用核心、核心遵守規則。UI 不自行解析控制文字，規則也不依賴特定 UI framework。

## 四組核心規則

正文只保留：

1. 分散推文聚合
2. 嵌套回文
3. 文章單純推噓和回文推噓
4. 回文編輯與撤回

每組以「PTT 的限制或輸入 → pttzzz 的理解 → 使用者看到的結果」描述。正文不使用逐條輸入／結果／限制表格；精確 pattern、時間與終止符邊界、去重、opaque payload 等內容集中到技術附錄。

## 正文案例

正文放五個簡化案例：

1. 同作者的分散推文聚合成一張卡。
2. 多層回文各自聚合後形成嵌套討論。
3. 純文章推噓與指定回文推噓的差異。
4. `推x樓` 加文字同時構成投票與嵌套回文。
5. 更正內容不重新解析，以及撤回後保留位置。

格式固定為「PTT 原始畫面 → pttzzz 結果 → 一句說明」，不顯示解析判定表。
