# Goal 11 自動分段回文 Implementation Notes

## 決策

- 規則 0.3.0 採 `|` 續接與 `_` 終止，不使用群組標頭；不再相容舊 `||`／`|!` 的特殊語意，一次只移除一個單字元尾標。
- 核心與 Web 均採非連續兩分鐘；連續片段不限時間，仍遵守作者、目標、控制與終止規則。
- 短文與長文末段皆須封口；已有自然終止標點不重複補記。中間片段只在需要時補 `|`，不是每段都加。
- 尚未確認的推文不得自動重送。保留已確認片段數與草稿，部分送達不視為完成。
- 真實容量不是固定 80。官方 `mbbsd/bbs.c` recommend 使用 maxlength 與含 NUL 的 getdata；確認畫面按 maxlength 補齊欄寬。取消的確認畫面作為目前終端的容量證據，避免猜測 IP 模式。
- 字元需通過 UAO encode/decode；不以非 ASCII 一律兩 bytes 取代實際編碼驗證。
- `_` 須占容量；末段是兩 bytes 字元時，退回一字可能使前段剩兩欄，因此補 `|` 維持滿行直接接續，避免多出換行。
- 分段前先快照完整輸入與 article key，避免非同步等待中被外部修改。登入世代變動後舊 operation 不得續送。
- 替換編輯內容原本會重走尾標消除，導致字面 `_`／`|` 遺失；改由無解析的片段串接函式處理，補齊替換、合併片段、附加與區段位移回歸測試。
- 舊 THREAD-005 是樓上回覆，維持編號不動；長文新規則使用 THREAD-006，fixture 同步。

## 限制

- 舊規則無法逐字保留任意尾空白及字面尾標。分段計畫先由真實聚合器還原驗證，不一致時不發送。
- 同帳號其他連線插話、跨客戶端未標記單段、控制事件仍可能影響聚合；不宣稱交易式原子性。
- 真實 PTT 測試限 Test 板的自建文章；測試完成後清理，不使用專案名稱發文。
- 草稿外緣空白／空白行正規化移除，正文內部空白行保留；行中尾標歧義與會被傳送層 trim 改寫的片段於送出前拒絕。
- `_` 只能阻止後方，不能避免第一片段與舊客戶端未封口前文接上；中途停止的內容也可能還沒有終止標記。
- UI receipt 保存於 Article 元件，modal 關閉／重開保留；離開文章或頁面重載不提供持久恢復。

## 草稿正規化與內容保留

- 將 CRLF 正規化為 LF，去除整份草稿最外緣的空白與空白行，再依 UAO 編碼計算 1,000 半形單位上限；LF 占一單位。
- 保留正文內部的換行與空白行。
- 片段邊界不得遺失字元或改變正文；字面尾標或空白若無法安全還原，須在送出前拒絕。

## 驗證範圍

- 白皮書 THREAD-006 改為 8 條後，接收 fixture 編號同步為第 4～8 條；第 1～3 條屬於送出限制，由 manifest 的 senderRules 指向 browser 可執行測試，不用接收 fixture 假裝驗證未送出的內容。

- browser 實作驗證 500 全形單位上限、實際容量及傳送狀態：500 中文字、1,000 英文字母及混合正文可送，多一個半形單位即拒絕，不送出任何片段；系統前綴和尾標不計入草稿額度。
- 討論事件 fixture 驗證讀回的合併結果。
- 不提供舊尾標語意的相容解析；不認識新版標記的客戶端可能直接顯示符號。
