# Goal 10 作者推噓防護與文章動作列設計

## 目標

本 Goal 同時整理文章頁的作者操作與兩種不同的回覆方式：

1. PTT 不允許作者推或噓自己的文章；PTTzzz 應在送出前停用按鈕並清楚說明原因。
2. 文章右上角統一顯示「刪除／編輯／回應」，移除原本會開啟推文輸入框的「回文」按鈕。
3. 「回應」使用 PTT 原生的回應至看板流程，建立一篇 `Re:` 文章；下方既有「回覆此文」則繼續新增文章推文，兩者不可混用。

## 文章右上角動作列

完整文章載入後，右上角固定依序顯示：

- `刪除`：只有登入者是文章作者且目前文章可安全定位時可用，否則保留按鈕並反灰。
- `編輯`：只有登入者是文章作者且目前文章可安全定位時可用，否則保留按鈕並反灰。
- `回應`：登入後可用，開啟回應至看板編輯器；未登入時反灰。

作者判斷一律使用 `normalizePttId()`，不受英文字母大小寫影響。編輯沿用現有 `compose-edit` 與 `editArticle` 流程，不新增另一套文章修改邏輯。

原本右上角會開啟推文 Composer 的「回文」按鈕移除。文章下方既有的「回覆此文」保留，仍負責一般推文／箭頭加註。

## 作者文章推噓防護

- 若目前使用者是文章作者，文章層級的「推」與「噓」按鈕保持顯示但設為 disabled。
- disabled 按鈕旁固定顯示：`作者不能推噓自己的文章，可使用回覆加註。`
- 「回覆此文」保持可用，讓作者使用 PTT 允許的箭頭類別加註。
- 非作者閱讀文章時，文章推噓 UI 與送出流程維持現況。
- 未登入時不顯示作者提示；既有文章推噓顯示方式不變。

`Article` 產生單一 `isArticleAuthor`，同時用於：

1. 文章動作列的刪除與編輯權限。
2. 傳入文章層級 `VotePair.disabled`。
3. 顯示作者限制提示。
4. 在 `handleArticleVote()` 開頭直接 return，防止程式呼叫或未來 UI 改動繞過 disabled button。

Adapter 現有防護不移除。若 UI 判斷因資料過期而未阻擋，PTT 回傳作者只能使用箭頭加註時，adapter 仍不得送出推或噓內容。

本次不修改回文卡片的推噓。作者仍可依現有規則對回文加分或扣分。

## 回應至看板流程

點擊右上角「回應」後，App 進入新的文章回應 Composer：

- 看板固定為原文看板，不可修改。
- 標題固定為單一 `Re: 原標題`，不可修改；若原標題已有 `Re:`，不重複疊加。
- 不顯示發文分類選擇。
- 正文必填，取消時回到原文章，失敗時保留草稿與錯誤訊息。
- 成功後回到原看板文章列表。

送出不得呼叫一般 `postArticle()`。Adapter 新增專用的 `replyArticleToBoard()`：在序列工作佇列內重新開啟原文章、核對作者與標題避免文章索引漂移，從文章頁執行 PTT 原生的回應至看板指令，再寫入正文並儲存。

PTT 原生回應編輯器可能自動帶入引文；本版 UI 沒有呈現引文，因此 adapter 會先清除原生預填內容，再寫入 Composer 中使用者可見的正文，確保預覽與實際發文一致。Fake adapter 同樣建立一篇新文章，使用正規化後的 `Re:` 標題與使用者輸入的正文。

一般文章索引與 AID 開啟的文章都可在有足夠定位資訊時回應。若缺少可安全定位原文的資料，「回應」保持顯示但 disabled，不降級成一般發文。

## 錯誤處理

- 作者點擊被停用的推噓按鈕不會觸發 handler，也不會送出 `X`、推或噓至 PTT。
- 刪除與編輯按鈕不因無權限而消失，避免使用者誤以為功能不存在；disabled 狀態表示目前帳號不可操作。
- 回應送出期間防止重複提交。
- 重新定位原文、文章身分核對、進入回應編輯器或儲存任一步失敗時，adapter 回傳失敗；UI 留在 Composer 並保留草稿。
- 不以一般發文作為回應失敗時的 fallback，以免建立標題相似但不是 PTT 原生回應的文章。

## 測試策略

- 作者 ID 完全相同或只有大小寫不同時，文章推與噓皆 disabled，並顯示固定提示。
- 作者觸發文章推噓 handler 時不呼叫 adapter action；非作者維持既有推噓行為。
- 回文卡片的推噓不因文章作者身分而停用。
- 右上角固定呈現刪除、編輯、回應，不再呈現會開啟推文 Composer 的「回文」。
- 非作者與未登入狀態下，刪除／編輯正確反灰；作者可進入既有編輯流程。
- 下方「回覆此文」仍可開啟一般推文 Composer。
- 回應 Composer 鎖定看板與單一 `Re:` 標題、隱藏分類，取消可回原文，失敗保留草稿，成功回看板。
- Adapter 測試驗證重新定位與文章身分核對、原生回應指令、清除預填引文、寫入正文及成功／失敗狀態。
- Fake adapter 測試驗證新增文章的標題、作者與正文。
- 執行相關測試、完整 `npm test`、lint 與 build。

所有自動化測試使用 mock 或 fake adapter，不會對真實 PTT 發文、推噓、編輯或刪除。

## 不在本階段處理

- 顯示或編輯 PTT 自動產生的引文。
- 自訂 tooltip、toast 或 modal。
- 修改 PTT 本身的作者限制。
- 其他 PTT 推噓失敗原因的專屬 UI 錯誤訊息。
